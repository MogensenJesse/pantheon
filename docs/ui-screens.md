# Save and skill screens

The DOM screens of the save system and the skill tree. The pure rules they read are in the Save system and Skills and abilities sections of `AGENTS.md`.

## Save screens (`src/ui/saves/`)

Built from the kit, styled by `saves.css` (tokens only). **Start screen** (`startScreen.ts`): sits in the overlay layer so the kit's panels open above it; Continue (newest save, with its day, villagers and age shown under the buttons), Load game, New game (asks first when saves exist), Settings; if storage cannot be read it says so and a new game does not save. **Slot lists** (`slotPanel.ts`, panels `slots-save` / `slots-load`): rows come from the pure `save/slotView.ts` (autosaves newest first and only when they exist, then three numbered slots; times in the player's local time). A used slot asks in its own row before it is replaced, loaded over or deleted (numbered slots only). `openConfirmPanel` is the generic question. **Pause menu** (`pauseMenu.ts`, panel `pause`): Resume, Save game, Load game, Settings, Quit to start (saves first; stays if that fails); opening it calls `GameLoop.setPaused(true)`, which stops fixed steps and passes a frame time of 0 to `render`, so the world and the play clock stand still while the frame keeps drawing. **When it opens** (`ui/pauseRules.ts`): Esc with the mouse free, or the mouse lock being lost with no panel open (the browser swallows Esc while locked, so the page only sees the lock go; this also covers alt-tabbing away). **Temple** (`templeSave.ts`): within the temple's footprint plus 14 m a hint "Press E to save" fades in and `E` opens the save list (hotkey `KeyE`). **Indicator** (`autosaveIndicator.ts`): "Saving" in the bottom right for at least 1.2 s per write

## Skill and ability screens (`src/ui/skills/`, `src/ui/abilities/`)

Built from the kit, styled by `skills.css` and `abilities.css` (tokens only). **Tree panel** (`skillPanel.ts`, modal panel `skills`, title "The Void"): the constellation is drawn by `constellation.ts` (nodes as real buttons plus one SVG for the lines) into the layer of `panZoomViewport.ts`; the panel updates itself from `skills:changed`, two tabs (The Void, The Village) swap the content in place; drag pans, wheel and the +/− buttons zoom, Centre resets; hover (or Shift) shows the kit tooltip; a click that is refused says why in a toast; Respec asks first. It opens with `pausesWorld` (the same freeze as the pause menu). What nodes look like and say, the edges and the pan/zoom maths are the pure `skills/skillView.ts`. **`skillUi.ts`**: `T` opens the panel once the tree exists; the "N sparks to spend · T" line shows while sparks are unspent; the first opening happens by itself after the Aethon memory has finished showing (`story:fragmentEnded` from `StoryLog.ts`), waits for any open panel, and falls back to 20 s after `skills:opened`. **Ability bar** (`abilityBar.ts`): bottom right, one slot per granted power with cost, a cooldown sweep and a word when it cannot be cast; hidden with no powers. **Radial menu** (`radialMenu.ts`, geometry in `abilities/radial.ts`): hold `Q` while the mouse is locked; mouse movement moves a virtual pointer (the camera does not turn: `CameraInputContext.setLookBlocked`), releasing `Q` casts the chosen sector, Esc or losing the lock or the window cancels. Both read an `AbilitySource` (`list()`), so a test power can drive the same code.
