# Quests: the engine, the quests that ship, and the last night

How quests run in the game. The design (what each quest is for, who speaks, why) is in [story-mechanics/QUESTS.md](../../story-mechanics/QUESTS.md); the conversion quest, belief and the conversion powers are in [hamlet-quest.md](hamlet-quest.md).

## The engine
- `src/quests/quest.ts` (pure, node-runnable): a quest is `QuestDef { id, kind, available?, intro?, steps }`; a step is `{ id, text, hidden?, goal?, advance(progress, event, ctx), reward? }` and a reward is `{ sparks?, beat?, fragment? }`. `QuestState { step, progress, done }` is plain data. `stepQuest(def, state, event, ctx)` feeds one event and one snapshot of the world and returns the new state and `QuestEffects { sparks, beats, fragments, completed, questDone }`. A step completes once, so nothing is rewarded twice, and finishing one cascades a `tick` so a step that is already true completes at once. `objectiveOf` gives the line to show; `parseQuest(raw, def)` accepts a saved state or says it is damaged.
- `QuestKind`: `main` (shows the objective line), `teaching`, `favour`, `finale`. Only the main quest shows a line; the elder asks the others (`story.ts`) and the world answers.
- `QuestEvent`: `tick`, `elderMet`, `signCast`, `deed { what, nearTemple, dusk }` (the hand put something down; the conversion quest's fire takes wood), `offered`, `plotPlaced`, `prayer { need, state }`, `heartened { mended, aera }`, `outpostDone { kind }`, `upgraded { building, level }`, `hunger { stage }`, `revealed`. Anything else that changes the world (a milestone reached, a place woken or restored) is just a `tick`: quests read it from the context.
- `QuestContext`: `converts`, `elderBelieves`, `converted`, `population`, `milestones`, `awake`, `prayersOpen`, `hunger`, `upgradable`, `allRestored`, and the last night's `dusk`, `orbAtTemple`, `energy`, `templeShare`.
- `src/quests/questLog.ts` (pure): `QuestsState` is a record by quest id (a quest not in it has not begun). `startQuests` begins the quests whose rule is true (every quest but the main one also needs `ctx.converted`; teaching quests begin one at a time and at most `PHASE0.QUEST.MAX_TEACHING_OPEN` are open) and returns each one's intro beat; `stepQuests` feeds an event to every quest that has begun; `parseQuests` drops ids the game no longer knows and refuses damage; `copyQuests`, `finishedQuests`.
- `src/quests/registry.ts`: `QUESTS`, in the order they are offered, and `QUEST_BY_ID`.
- `src/quests/content/`: the quests themselves. `conversion.ts` (the conversion quest and its pure rules: `elderMeets`, `offeringRate`, `elderOpenToBelief`, `sparksForConvert`, `isDusk`), `teaching.ts`, `favours.ts`, `finale.ts`, and `questBuilders.ts` (`oneStepQuest`, the shape teaching quests and favours share: intro `<id>-ask`, closing `<id>-done`, one spark, an optional fragment).
- `src/quests/busEvents.ts`: how a bus event reaches a quest (an outpost finished becomes `outpostDone`; a place of power being restored is not one).
- `src/quests/questRuntime.ts` (`initQuest`): looks at the world every `PHASE0.QUEST.TICK_S` and on the bus (`village:plotPlaced`, `:prayer`, `:heartened`, `:outpost`, `:upgraded`, `:hunger`, `:villagerConverted`, `ability:cast` for the Sign, `milestone:reached`, `landmark:awakened`, `landmark:restored`). It builds the context once per event, begins and steps the quests, pays sparks, emits `story:beat` and `memory:trigger`, and when the conversion quest ends converts the village. It emits `objective:changed` when a quest began, moved a step or moved a whole unit of progress, and `quest:done { id }` when one finishes. A conversion that did not come from the quest (a DEV shortcut) ends the conversion quest too.
- `quest:done { id }` is the one signal that a quest finished: `gameplay/progression.ts` moves the game to phase 3 on the last night's; the memory book and the `name_returned` milestone read `isDone` of the same quest.
- Only a hamlet has quests; a DEV `?sandbox` village has none. Saved as the profile's `quests` slice (`parseQuests`, save version 17).

## Teaching quests and favours
- Eight teaching quests (data in `content/teaching.ts`): First Roof (a plot is placed), A Prayer Heard (a prayer is answered), The Touch (a lapsed believer or a prayer is set right by Hearten), Raised (milestone `level_2`), The First Place (milestone `first_place`), Beyond the Fence (an outpost is finished), A Hard Winter (hunger recovers), Many Hands (milestone `folk_20`; begins at `PHASE0.QUEST.MANY_HANDS_FROM` villagers). Each begins when its mechanic is open and is done by doing the thing once.
- Five favours (`content/favours.ts`), one per place, asked once the place is awake and the village converted: runestones: answer three prayers; tree: answer a prayer for rain; temple_ruin: raise a house to level 2; sunken_ruin: build a fishing hut; monolith: Hearten Aera. Each pays a spark and tells a memory fragment (`FRAGMENT_IDS.favour`, ids 18 to 22).
- `village:heartened` carries `mended` (a lapsed believer or a prayer set right) and `aera`.
- Check: `npm run check:quest-content`.

## Who speaks
`src/story/story.ts` has one table, `BEATS`: beat id to `{ speaker?, lines }`. A beat with a `speaker` (`caros` or `aera`, names in `SPEAKER_NAMES`) is said by that character; one without is the old god's narration. `beatPayload(id)` gives what the log is told; `story:beat` carries the resolved display name, so `StoryLog` shows it above the card (`.story-speaker`, upright text) and keeps the narrator's italics for the rest. Memory fragments are in `story/fragments.ts` (`MEMORY_FRAGMENTS`; `FRAGMENT_IDS` names the ones told by a quest). All lines are placeholders. `check:quest-content` fails for a beat a quest uses that has no lines, a beat no quest uses, or an unknown speaker.

## Aera
A fixed villager of the hamlet (`sim.aera`, the first idler who is not the elder; saved, and her index follows `villagerDied` moves like the elder's, through `followMove`). She stays an idler (`population.promoteFarmers` skips her), and `pickVictim` never picks her, so a quest that needs her cannot be lost to famine. The overview names her and the elder ("Caros, the elder"). The monolith favour asks the player to Hearten her, and she answers in her own voice.

## The last night
Quest `name` (`content/finale.ts`, kind `finale`) begins when the village is converted and every place of power is restored (Caros calls the village to the temple). Two hidden steps:
1. `gather`: at dusk, the orb within `FINALE.TEMPLE_M` of the temple with at least `FINALE.MIN_ENERGY`, and at least `FINALE.GATHER_SHARE` of the villagers believing and standing within `FINALE.TEMPLE_R_M` of it (`sim.gatheredShare(r)`; lapsed or starved villagers do not count). While this step waits, and through the next one, the runtime sets `village.setGathering(true)`: in the sim `RoutineWorld.gathering` sends every villager to pray at the temple after `WORK_END`, rain or not (see [routine](routine.md)). If the gathering is not met the village waits for the next dusk; there is no fail state and no objective line.
2. `reveal`: the runtime plays the cutscene (`deps.playFinale(done)`, which `initGameplay` wires to `createFinaleCutscene(...).play`; it starts from the saved step, so a reload in the middle replays it) and `done` feeds the `revealed` event. It pays `FINALE.SPARKS`, the beat `finale-done` and fragment 23, emits `quest:done`, the game reaches phase 3 and the milestone `name_returned` is recorded.

## The cutscene (`src/finale/`, `src/rendering/cinematic.ts`)
- `finale/timeline.ts` (pure): `buildFinaleTimeline(places, temple).at(t)` gives the view (an orbit: ground point, height looked at, distance, yaw, pitch), each place's beam strength, each rune stroke's progress and the rune's glow. The opening look at the gathering, a slot per place (the view glides there, a beam rises), then the view returns to the temple and looks up; in that return shot the strokes of the rune light one after another and the whole rune glows and holds. Numbers: `PHASE0.QUEST.FINALE.CUTSCENE` (about 33 s with five places).
- `rendering/cinematic.ts`: the camera director. It poses the camera from a script, eases in from where the camera was, takes the movement keys, moves the detail centre (grass, props, shadows) to what is looked at, drops the depth-of-field and, at the end or on a skip (which glides to the end state first), hands the camera to the follow rig, which glides it home. `gameTick` lets it pose the camera over the overview; the overview cannot open while it plays (`blocked`).
- `finale/cutscene.ts`: plays the timeline through the director, shows the "Press Space to skip" hint, binds Space and Enter (not while a panel is open, so the pause menu keeps its keys), holds the mouse look and takes the player out of the overview first (the village HUD hides itself while it plays). A second `play` while one runs is ignored.
- `finale/scene.ts`: a `createCrownBeam` per place and the rune, with their levels. Out of the cutscene the levels ease to a faint rest (`BEAM_SETTLED`, `RUNE_SETTLED`) once the name has returned, also after a load. Nothing is built until a cutscene plays or the name has returned.
- `finale/rune.ts`: five additive ribbons from `RUNE_STROKES`, drawn along their stroke as it lights and turned to face the camera. Shared look: `createAdditiveGlowMaterial` (`rendering/glowMaterial.ts`), `config/visual/finale.ts`.
- DEV: `__pantheonQuest.playCutscene()` plays it alone. Checks: `check:finale` (the timeline), `check:cinematic` (the director). The look on a real GPU is manual (`story-mechanics/PHASE_0_TODO.md`).

## Screens
`src/ui/quests/`: a quiet objective line at the top left (`.q-objective`, with a counter for counted steps; the conversion quest's, then the restoration goals) and the **memory book** on `J` (modal panel, freezes the world; `quests/memoryBook.ts` builds it, `ui/quests/runeView.ts` draws its cover): the rune (five strokes from `config/visual/rune.ts`, one lit per restored place, all once the name returns), the memories found, the places woken with their captions and what they do for the village, and the milestones reached. No to-do list. The elder has a larger pip (`.po-pip.is-elder`) after the meeting.

## Checks
`check:quests` (the engine, the conversion quest, several quests at once, the memory book), `check:quest-content` (teaching quests, favours, the last night, the story table), `check:finale`, `check:cinematic`. They share `scripts/checks/lib/questFixtures.ts`. `check:village-routine` covers the gathering in the sim, including that its hours lie inside what the quests call dusk.
